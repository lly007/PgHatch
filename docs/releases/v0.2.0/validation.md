## 诊断与配置机制

原 v0.1.1 在隔离夹具中复现：缺失 Binaries/Instances 均抛出格式/版本错误；合法 JSON 的失联引用导致整个配置被拒绝；真正语法截断由 JsonException 报告。修复后前两类可加载且保留实例，语法错误、字段类型与语义错误分别提供具体原因，不自动重置配置。测试入口 `--config-repro` 在原逻辑和新逻辑各运行过。

缺失/空的集合使用空列表，null 可选布尔字段使用 false，缺失版本按 schema 1；当前保存 schema 2。不受支持的未来版本拒绝加载和常规保存。失联 BinaryId（包括缺失的 ID）保留为可修复状态。缺失程序文件不属于整个配置文件的语义损坏。

保存先完整序列化并验证，再写同目录临时文件、flush 到磁盘，使用 File.Replace / 首次 File.Move。相同路径的保存共享串行锁，保存前核对加载时内容指纹。冲突取消保存，请重读后重新应用修改；不自动合并。文件系统异常时保留正式文件，临时文件正常清理。备份只来自有效当前配置；损坏当前文件无法覆盖有效备份。

恢复必须由用户确认，先验证 `.bak` 的 JSON、字段、schema 和实例引用，再保存损坏原文到唯一 `.preserved-*` 文件。备份有问题则拒绝恢复，不反复尝试；允许保留原文后明确选择空白配置。只读目录不会回退到别处保存。

新文件优先，缺少新文件才迁移旧文件，迁移时锁住旧源文件以避免同时编辑，旧文件原样留下。相对路径仍相对于 EXE 同目录。新文件损坏时不自动使用旧文件，更不会混合两份登记。旧版无法读取新 schema；不要把 schema 2 配置复制回旧文件供旧版使用。

## 自动化结果

最终 Release 编译：0 警告、0 错误（`build-results.txt`）。

配置/迁移/注册：75 项 PASS（`config-results.txt`），使用新建的 `D:\PGTray-Test\v020-config-*` 隔离夹具；含用户列出的 27 类配置/迁移/注册场景以及 BOM、重复字段、类型、未来版本、异常替换、跨存储对象陈旧快照等。目录版本检查的快速测试使用明确标识的元数据夹具，不把它当作完整真实集群测试。

覆盖真实 initdb/SCRAM/SQL、中文与空格路径、自定义 127.0.0.2、双实例独立启停/重启、同端口不同地址的 PID 归属、端口冲突、pg_ctl 零等待超时后的真实状态、warm standby 的 Starting/NotReady、嵌套/junction 防护、扫描全目录哈希不变、轮询竞争、退出协调器后 PostgreSQL 继续运行、重开协调器识别状态。新增运行中实例失联后拒绝停止、重新关联恢复 Ready、失效程序修复路径且 SQL 继续可用。

端点查询不可用场景使用注入失败，但被测服务器是真实进程；未将此项表述为真实系统端点故障。跨版本拒绝使用 PG17 元数据/PG18 实际工具，未声称安装并完整测试了 PG17。

开发过程中旧测试仍按 JsonException 捕获配置语法错误，首次全套运行在恢复断言处中止；已更新为明确的 InvalidDataException，随后全套通过。无待修复的自动化失败。

## 环境和真实数据边界

- Windows x64，系统版本由 .NET 报告为 10.0.28000；SDK 10.0.402，Desktop Runtime 10.0.13。
- 起始工作目录为空，未发现现有工程或适用 AGENTS.md。
- 只读检查发现程序目录为 `D:\PostgreSQL\PostgreSQL\bin`，`postgres --version` 为 18.6。
- 真实集群为 `D:\PostgreSQL\PGData\main`，`PG_VERSION` 为 18；原配置 `127.0.0.1:5432`，logging_collector 开启，log_directory 为 `../logs`。
- 真实集群初始和结束时 `pg_ctl status` 均为 no server running。没有对它执行 initdb、启停、配置改写、删除或重置，也没有注册到本次 GUI 测试配置中。
- 所有写入和数据库生命周期测试都在 `D:\PGTray-Test\run-*` 下的本次新建集群执行。测试目录有 `.pgtray-test-owned` 归属标记。最终检查未发现残留 postgres.exe；测试数据和日志保留以便复核，没有递归删除真实或测试数据。

## 最终自动化运行

命令：

```powershell
dotnet build PGTray.sln -c Release
dotnet run --project tests/PGTray.IntegrationTests -c Release -- 'D:\PostgreSQL\PostgreSQL' 'D:\PGTray-Test'
```

最终完整运行退出码为 0，34 项 PASS。34 项原始输出的结论已归入本报告的覆盖范围和验收映射。原测试资源位于 `D:\PGTray-Test\run-20261017-190529-d4b23a8d`。该轮已包含 `initdb --no-clean`，失败时保留专用目标目录供检查。

覆盖：ZIP 工具发现、缺失工具、已有集群导入、只读读取端口、中文及空格 PGDATA、真实密码 SQL 连接、SCRAM 哈希检查、fast stop、多实例并行、重启、独立停止、重加载识别、移除配置保留运行数据库、重命名持久化、相对路径、整体迁移、重复目录/端口、非空目录保护、端口占用、启动错误及返回码、最近操作保留、同实例并发拒绝、命令超时、配置被占用、损坏 JSON、实际 ACL 无写权限和 initdb 权限失败、临时密码文件清理。

主版本不兼容验证使用专门构造的测试 PG_VERSION=17 元数据及空 pg_control 占位文件，验证在调用 pg_ctl 之前拒绝；它不是完整 PostgreSQL 17 集群交叉运行测试。命令超时测试使用测试程序自身的延迟子进程；未模拟真实 PostgreSQL 长时间崩溃恢复。

早期实测发现 Windows 后台服务器继承管道句柄会导致 ReadToEndAsync 等不到 EOF。现已改为进程完成后有界排空输出；后续所有真实启停均完成，避免将控制器退出等同于服务器已停止。

## 实际 GUI 验证

通过 computer-use 技能控制本机 WinForms 窗口，对最终发布 EXE 的独立副本验证。GUI 副本位于 `D:\PGTray-Test\gui-20261017-1858`，只包含专用测试实例配置。

- 主窗口能够显示两个实例、版本、端口与真实状态；中文工具输出正常显示。
- 点击“启动”，独立测试集群进入 Running；点击“停止”后进入 Stopped，最近操作中保留 fast stop 的成功输出。
- 新建实例对话框可打开，名称、程序、路径、端口、超级用户、密码字段及按钮布局正常。本轮 GUI 没有提交第三个新集群；新建流程由真实集成测试覆盖。
- 使用 Ctrl+Q 正常退出管理器后，`pg_ctl status` 仍报告同一测试服务器运行。重新打开最终 EXE 后显示 Running。
- 关闭主窗口后不再有可见窗口，PGTray 进程继续存活；再次启动 EXE 恢复同一个管理窗口。
- 修复轮询重建表格导致选择受影响的问题，改为原位更新行。
- GUI 验证结束后测试数据库已正常停止。
